## 2026-07-27 — [workflow] Green gate + 93 passing tests cannot detect a missing core feature; diffed two independent solutions of task 16 against legacy to surface the gap

Why: Task 16 (`screen-bill-balance-rates`) shipped two independent implementations. One completely omitted the screen's core behavior — balance converted to foreign currencies (UAH/USD/EUR) as the legacy `page-bill` screen renders three times over. It shipped a raw account balance card and raw FX rate table instead. This fully-absent feature passed the entire mandatory quality gate: `tester` green (93 tests passing, no coverage gap visible), `reviewer` green, `qa` green, lint/typecheck/build all green, knowledge capture completed, METRICS.md row added. No gate stage flags it because every stage verifies only code that was built; a feature never written has no diff to review, no code to cover, no flow to exercise. The absence surfaced only by diffing two independent solutions against the legacy `page-bill` code in git — this is the concrete evidence that justified adding Phase 4.5 (orchestrator acceptance verification) as a mandatory step after the quality gate and before `docs-writer`. Without this counter-example, the new phase reads as generic process advice and is likely to be distilled away on the next workflow review. Belongs in (guess): `rules/local/workflow.md` § Phase 4.5 — Acceptance Verification (this is the motivating evidence justifying that rule; delete this entry once the rule proves durable through a second/third implementation cycle where it catches a real gap).

## 2026-07-28 — [testing] `HttpTestingController.expectOne(url)` ignores HTTP method — ambiguous when two ops share a URL

Why: While splitting per-operation `BudgetRequestState` in `category.store.ts`/`transaction.store.ts`/`monthly-budget.store.ts`, isolation tests needed to flush two concurrent requests to the same path (e.g. GET list vs POST create/record, GET vs PUT upsert). `expectOne('/path')` as a bare string matches on `TestRequest.url` only — no query params, no method — so it silently matches whichever pending request has that path regardless of verb, producing false-pass tests that don't actually isolate the two operations. Fix: pass a predicate checking both `candidate.url` and `candidate.method`. Belongs in (guess): `rules/local/code-style-angular.md` or a testing rule covering `HttpTestingController` patterns.
