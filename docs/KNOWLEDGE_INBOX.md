## 2026-07-27 — [workflow] Green gate + 93 passing tests cannot detect a missing core feature; diffed two independent solutions of task 16 against legacy to surface the gap

Why: Task 16 (`screen-bill-balance-rates`) shipped two independent implementations. One completely omitted the screen's core behavior — balance converted to foreign currencies (UAH/USD/EUR) as the legacy `page-bill` screen renders three times over. It shipped a raw account balance card and raw FX rate table instead. This fully-absent feature passed the entire mandatory quality gate: `tester` green (93 tests passing, no coverage gap visible), `reviewer` green, `qa` green, lint/typecheck/build all green, knowledge capture completed, METRICS.md row added. No gate stage flags it because every stage verifies only code that was built; a feature never written has no diff to review, no code to cover, no flow to exercise. The absence surfaced only by diffing two independent solutions against the legacy `page-bill` code in git — this is the concrete evidence that justified adding Phase 4.5 (orchestrator acceptance verification) as a mandatory step after the quality gate and before `docs-writer`. Without this counter-example, the new phase reads as generic process advice and is likely to be distilled away on the next workflow review. Belongs in (guess): `rules/local/workflow.md` § Phase 4.5 — Acceptance Verification (this is the motivating evidence justifying that rule; delete this entry once the rule proves durable through a second/third implementation cycle where it catches a real gap).

## 2026-07-28 — [testing] `HttpTestingController.expectOne(url)` ignores HTTP method — ambiguous when two ops share a URL

Why: While splitting per-operation `BudgetRequestState` in `category.store.ts`/`transaction.store.ts`/`monthly-budget.store.ts`, isolation tests needed to flush two concurrent requests to the same path (e.g. GET list vs POST create/record, GET vs PUT upsert). `expectOne('/path')` as a bare string matches on `TestRequest.url` only — no query params, no method — so it silently matches whichever pending request has that path regardless of verb, producing false-pass tests that don't actually isolate the two operations. Fix: pass a predicate checking both `candidate.url` and `candidate.method`. Belongs in (guess): `rules/local/code-style-angular.md` or a testing rule covering `HttpTestingController` patterns.

## 2026-07-28 — [build] Tailwind v4 `@source` globs in `apps/web/src/styles.css` are per-lib opt-in; a new Nx lib with templates renders unstyled until added

Why: `libs/budget/ui` and `libs/budget/feature-account` templates (account page, balance-card, rates-card) already used correct ADR-009 utility classes (`rounded-card`, `bg-surface`, etc.) but rendered with browser defaults because their paths weren't in the `@source` list — only identity libs and `shared/web-shell` were scanned. Failure is silent: no build error, no lint error, classes just don't generate CSS unless they happen to overlap with an already-scanned path's usage (masked the bug here). Fixed in `2026-07-28-02-tailwind-source-globs-missing-budget-libs`. Belongs in (guess): `rules/local/architecture-angular.md` (new lib checklist: add its template path to `styles.css` `@source`) or `rules/cts/nx-generators.md`. A static regression guard now exists: `apps/web/src/tailwind-source-globs.guard.spec.ts` (parses `@source` globs, flags any `libs/*/*/src` dir with `.html` templates not covered).

## 2026-07-28 — [process] `git checkout -- <file>` / `git restore` on an uncommitted-only change silently destroys it, no warning

Why: While independently verifying the `@source` glob fix above, the `tester` agent used `git checkout -- apps/web/src/styles.css` as a "revert to confirm RED" trick — but since the fix was never committed, this reverted all the way to HEAD (pre-fix), destroying the implementer's diff. Caught only because a regression test then failed unexpectedly; manually re-applied the two lines from memory of the diff. Fix/rule: when a quality-gate agent needs to temporarily revert an uncommitted change to test RED/GREEN, use `cp file /tmp/...` or `git stash`/`git stash pop`, never `git checkout --`/`git restore` — those assume there's a committed version to fall back to. Belongs in (guess): `rules/cts/workflow.md` (tester/quality-gate agent conventions) or `rules/cts/git-operations.md`.

## 2026-07-28 — [config] CLI has no dotenv loader; requires manual shell env sourcing

Why: `apps/cli/src/config/cli-config.ts` reads `MONGO_URI`/`MONGO_DB_NAME` directly from `process.env` with no dotenv import anywhere in the codebase (`grep "dotenv" apps/** libs/** = 0`). Running CLI commands without prefixing `set -a && source .env && set +a` fails silently — database connection error is generic "failed to connect", not "missing MONGO_URI". Only two of four CLI examples in README/SKELETON had the prefix; the generic intro line was missing it. All CLI invocations now uniformly documented with the prefix; this entry prevents backsliding when new commands or examples are authored. Belongs in (guess): `rules/local/code-style-backend.md` (backend config/env setup checklist) once distilled.
